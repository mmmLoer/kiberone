# KIBERone Hub: действующий сервер

6 октября 2026 Hub обновлён бинарником с API `POST /api/vpn/reservations/lookup` и
`POST /api/vpn/reservations`. Он атомарно закрепляет WireGuard-слот и отпечаток
ключа за `location + client_id`; данные лежат в
`/var/lib/kiberone-hub/vpn/reservations.json`. Запасная копия прежнего бинарника:
`/opt/kiberone-hub/Kiberone.Hub.backup-20261006`. После замены служба и health
ответили, запрос к новому API с неверным паролем вернул 403.

Новый Tutor требует этот Hub и пароль локации перед выдачей VPN. Старые
установленные профили не имеют записей в реестре; их нужно импортировать или
перераспределить до массового включения, иначе уникальность исторических
назначений не подтверждена. На доступном NL VPN-сервере 180 слотов суммарно,
но для локации ШБ доступно 15; DE/FR API при проверке не ответил.

С 6 октября 2026 Hub для данных локаций и обновления Student работает на `193.182.145.64:8787` (hostname `netherlands`). Второй проверенный сервер `188.190.22.99` (hostname `germany`) Hub не содержит. Старый адрес `193.235.147.228:8787` во время переноса не отвечал.

На сервере: исполняемый файл `/opt/kiberone-hub/Kiberone.Hub`; служба `kiberone-hub.service` под отдельным пользователем `kiberone-hub`; данные `/var/lib/kiberone-hub/`; хеши паролей `location-secrets.json`; снимки `/var/lib/kiberone-hub/rosters/`; обновление `/var/lib/kiberone-hub/updates/KIBERoneStudent.exe` и `student_manifest.json`. Порт 8787 разрешён в UFW. Служба запускается автоматически.

На Windows-компьютере сборки локальная копия паролей локаций лежит в `%LOCALAPPDATA%\KiberoneHubMigration\location-passwords.json`, хеши — в `location-secrets.json`. Оба файла находятся **вне репозитория**. Пароли новые; старые пароли прежнего Hub здесь не действуют. Перенесён доступный локальный снимок локации `ШБ` (8 групп, 1 ученик). Данные остальных локаций на старом сервере получить не удалось; их нужно загрузить из Tutor, если сохранились локальные базы.

Проверка без изменения данных:

```bash
ssh root@193.182.145.64 'systemctl is-active kiberone-hub; ls -lh /var/lib/kiberone-hub/updates/'
curl http://193.182.145.64:8787/api/health
curl http://193.182.145.64:8787/api/update/student
```

Стабильная сборка обновления — 0.10.40. Manifest подписывается RSA-PSS/SHA-256; одной контрольной суммы недостаточно. Закрытый ключ находится **только** на Windows-компьютере сборки в `%LOCALAPPDATA%\KiberoneHubMigration\student-update-signing-private.pem`; резервную копию храните отдельно и не кладите ключ в Git или на Hub. Публичный ключ встроен в клиент. Для подписи на другой машине задайте `KIBERONE_UPDATE_SIGNING_KEY_PATH` и выполните:

```bash
dotnet run --project tools/Kiberone.UpdateSigner/Kiberone.UpdateSigner.csproj -c Release -- path/to/Kiberone.Student.exe 0.10.41 path/to/student_manifest.json
```

Чтобы опубликовать следующее обновление Student, соберите **одиночный** `win-x64` EXE (`PublishSingleFile=true`), подпишите его указанной командой, загрузите EXE во временный файл на сервере и проверьте там SHA-256. Затем замените `updates/KIBERoneStudent.exe` и **последним** — `updates/student_manifest.json`. Файлы должны принадлежать `kiberone-hub` и быть доступны ему для чтения. Версию в `BuildInfo.Version` увеличьте перед сборкой. Автоматическая сборка по push на этом сервере не настроена.

Для цепочки Hub → Tutor → Student нужен Tutor со свежим кодом проверки подписи. Старые установленные Student имеют ошибку подготовки обновления, поэтому до использования автоматического обновления их следует **один раз** обновить установщиком 0.10.40 с правами администратора. Дальнейшее обновление использует установленную VPN bridge-службу и не вызывает UAC; работу именно на установленной Windows-машине ещё нужно проверить, когда тестовая VM будет доступна.

## Тестовое обновление Student 0.10.41 (7 октября 2026)

На действующем Hub размещён подписанный `KIBERoneStudent.exe` версии 0.10.41 в `/var/lib/kiberone-hub/updates/test/`. Его SHA-256: `d6297c43b5d33cdfa46c0a74c52daadea154c3d36b046e239cfb4d9fe83de169`, размер 221620225 байт. API: `GET /api/update/student?channel=test` и `GET /api/update/student/file?channel=test`. Обычные адреса без `channel=test` по-прежнему отдают 0.10.40. Служба Hub запущена; метаданные тестового канала ответили 200, частичное скачивание — 206 с ожидаемым размером.

Для ручной проверки откройте установленный Tutor 0.10.41 на тестовой машине. В «Настройках» оставьте включённым «Разрешить обновления Student», включите «Тестовый канал обновлений Student на этом Tutor», нажмите «Сохранить настройки», затем «Скачать обновление Student с сервера». Подключите установленный Student 0.10.40 к этому Tutor и нажмите у ученика «Установить обновление». После перезапуска проверьте версию 0.10.41. Тестовый переключатель сейчас оставлен выключенным; при его включении обновление может получить любой Student, подключившийся к **этому** Tutor. После проверки выключите переключатель и сохраните настройки.

Проверка полного скачивания и установки на удалённой Windows-машине остаётся за ручным тестом. Канал Hub обновляет Student; обновления Tutor через этот API пока нет. Бинарник Hub до добавления тестового канала сохранён как `/opt/kiberone-hub/Kiberone.Hub.before-testchannel-20261006`.

API пока доступен по обычному HTTP; пароль локации и данные проходят без шифрования. Перед использованием через недоверенные сети следует настроить HTTPS и обновить URL Tutor.

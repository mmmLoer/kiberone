# Device identity enrollment and migration

Student HTTP requests and command WebSocket handshakes now require both the discovery sync token and X-Client-Id / X-Client-Secret. The secret is 32 random bytes encoded as 64 hexadecimal characters. There is no default legacy fallback. /health remains public; authenticated tutor calls (X-Tutor: 1 and the tutor token, plus the sync token) bypass device authentication.

Student secrets persist under %LOCALAPPDATA%\KIBERone Classroom\device-secrets. Tutor pins persist under its data directory (%LOCALAPPDATA%\KIBERone Classroom\device-pins in the desktop app). Each filename hashes the case-insensitive client ID. Tutor files contain only the SHA-256 secret hash. Enrollment publishes an immutable file atomically after flushing it; a restart, offline client, or empty ClientRegistry never releases a claimed ID. Corrupt/unreadable storage fails closed.

First contact is trust on first use: the first valid device credential presented with the sync token claims an unclaimed ID. Deploy and enroll on a trusted classroom network. A peer holding the sync token can claim an ID before the legitimate device enrolls; this scheme does not authenticate first contact or provide TLS. Local HTTP exposes credentials to network interception. TLS/local transport migration is deferred. Student name selection remains normal; this protects device identity, not proof that a person chose their own name.

Upgrade Student agents and Tutor together. Old Students without a secret are rejected by the new Tutor, including roster/update requests; distribute the upgrade through the installer or deployment tools before upgrading Tutor. New Students can still talk to old Tutors, but those Tutors do not enforce protection. Preserve device-secrets and device-pins in backups/reinstalls, and do not clone Student secrets between PCs. Moving between OS user profiles requires preserving the matching device secret. An intentional device replacement/secret loss requires stopping Tutor and removing only the affected pin under administrator control, then re-enrolling on a trusted network; do not delete all pins to resolve a single conflict.

The server requires body/query client IDs to match authenticated headers for heartbeat, sync preparation/completion and client_id routes. Sync preparation may bind a student only when that student matches the device's current heartbeat selection. Presence and command socket operations inherit the authenticated device identity.

WebSocket clients may supply token, client_id and client_secret in the handshake query when headers are unavailable. Headers take precedence and the query client_id must match the authenticated identity. StudentAgent sends secrets only in headers; query credentials can appear in HTTP access logs and should be reserved for clients that require them.

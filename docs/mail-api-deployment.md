# Действующий почтовый API

Развёрнут 7 октября 2026 на `193.182.145.64`:

- HTTPS: `https://nshub.pro/api/mail/`
- Проверка: `GET /api/mail/health`
- Выдача ящика: `POST /api/mail/accounts` с JSON `location`, `password` (пароль локации), `studentId`. Только ученики в сохранённом roster локации.
- Входящие: `GET /api/mail/inbox` с заголовками `X-Mailbox-Id` (GUID ученика), `X-Mailbox-Password` (выданный пароль). Ответ — до 50 последних MIME-писем.

Пароль и адрес постоянны для GUID ученика. Пароли не выводятся тестовым скриптом. Ответы с учётными данными и письмами имеют `Cache-Control: no-store`. Пароль предназначен для API KIBERone, не для SMTP/IMAP. Исходящая почта не реализована.

## Сервер

Отдельная служба `kiberone-mail-api.service`, бинарник `/opt/kiberone-mail-api/Kiberone.MailApi`, внутренний адрес `127.0.0.1:8790`. Порт не открыт наружу. Служба запускается автоматически; systemd ограничивает запись каталогами почты, Postfix и учётных данных API. Создание Maildir и обновление Postfix выполняются root внутри этой службы. Для `postmap` требуется AF_NETLINK, чтобы прочитать список сетевых интерфейсов.

Данные:

- Пароли: `/var/lib/kiberone-hub/mail-accounts/<student-guid>.json`, каталог 0700, файлы 0600, владелец root.
- Письма: `/var/mail/nshub/students.nshub.pro/s-<student-guid>/Maildir/`, владелец существующий `vmail`.
- Карта Postfix: `/etc/postfix/vmailbox` и `.db`.
- Nginx: отдельный `location ^~ /api/mail/` на 8790; остальные `/api/` по-прежнему направляются в портал на 3000. Ограничение частоты 5 запросов/с на IP с burst 20.

Существующая служба Hub, бинарник Hub и manifest обновления Student не менялись. Резервная копия конфигурации nginx, Postfix-карты, файла паролей локаций и контрольных сумм: `/root/kiberone-mail-api-backup-20261007T193957Z/`. Она доступна только root.

## Сборка и обновление

```powershell
dotnet publish src/Kiberone.MailApi/Kiberone.MailApi.csproj -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o dist/MailApi-linux-x64
```

Перед передачей shell-скриптов и unit-файла преобразовать CRLF в LF без BOM. Передать бинарник и файлы `deploy/provision-student-mailbox.sh`, `deploy/kiberone-mail-api.service`, `deploy/install-mail-api.sh` в `/root/kiberone-mail-api-stage/` и выполнить `bash /root/kiberone-mail-api-stage/install-mail-api.sh`. После обновления проверить HTTPS health и логи `journalctl -u kiberone-mail-api`.

Постоянные Maildir и `mail-accounts` сохранять при любых обновлениях и резервировать: удаление JSON сменит пароль.

## Клиент и проверка

В Tutor указан по умолчанию `https://nshub.pro/`. Для выдачи почты нужно указать пароль своей локации в настройках Tutor. Затем у ученика открыть «Почта» и обновить входящие.

Проверено на действующем сервере: HTTPS с проверкой сертификата, повторная выдача того же пароля, доставка тестового письма через локальный Postfix и чтение по HTTPS, извлечение кода, отказ с неверным паролем (401), отказ для ученика вне roster (403). После перезапуска API данные сохранились. Публичный портал и health старого Hub отвечают, контрольные суммы Hub и manifest совпадают с исходными. Проверка внешней доставки от конкретных сайтов не выполнялась в этой задаче.

На Windows сборки `scripts/test-mail-api.ps1` берёт пароль локации из существующего приватного `%LOCALAPPDATA%/KiberoneHubMigration/location-passwords.json`, а GUID — через SSH из roster. `-Delivery` отправляет новое тестовое письмо существующему ученику; без этого флага проверяются API и доступ к входящим. Пароль ящика не печатается. Все 137 автоматических тестов прошли, включая HTTP-проверку авторизации почтового API.


## Обновление 2026-10-07: адреса, оформление и срок хранения

Адрес создаётся из транслитерированных фамилии и имени. Совпадения получают суффикс 2, 3 и далее. Для ранее выданного GUID-адреса создаётся новый именованный адрес, пароль и Maildir сохраняются; старый адрес продолжает принимать письма. Проверена доставка на gorohovmatvey@students.nshub.pro.

Письма удаляются через 24 часа с момента доставки, определяемого временем файла Maildir, а не заголовком отправителя. API очищает ящики при чтении и каждую минуту в фоне. JSON с адресом и паролем не удаляется. Открытый просроченный текст удаляется из памяти клиента.

HTML-просмотр работает через WebView2 в приватном профиле: оформление, HTTPS-картинки и вложенные CID-изображения поддерживаются. Скрипты, формы, встроенные страницы, загрузки и автоматические переходы отключены. При отсутствии WebView2 Runtime показывается текст письма и кнопки ссылок; клиент не пытается устанавливать Runtime и не вызывает UAC. Для полного оформления на чистой Windows нужен установленный Microsoft Edge WebView2 Runtime.

Проверено настоящее письмо Figma во встроенном просмотрщике. 128 тестов без VPN прошли. Реальные VPN-тесты теперь требуют явного KIBERONE_TEST_REAL_VPN=1 и предназначены только для тестовой VM. В начале этой проверки общий набор ошибочно запустил старый тест подключения к службе и получил ошибку; дальнейшие запуски полностью исключали VPN.


## Однократный ввод пароля локации

Тьютор вводит пароль в мастере первой настройки или перед первым обменом данными с сервером. После успешной загрузки, отправки списка учеников либо выдачи ящика пароль сохраняется защищённо. В Windows это DPAPI CurrentUser в LocalAppData/KIBERone/Tutor/credentials; на macOS — Keychain. В settings.json пароль не записывается. При запуске и смене локации восстанавливается пароль именно этой локации и этого адреса сервера. Неверный пароль не заменяет ранее сохранённый. После отправки данных пароль больше не очищается. Если пароль изменили на сервере, его можно заменить в настройках при следующем успешном обмене.

Проверены шифрование, повторное чтение новым экземпляром хранилища, замена пароля и изоляция локаций/серверов на Windows. macOS-реализация собрана, но на Mac в этой задаче не запускалась.

Автоматическая выдача новым ученикам: Mail API добавляет отсутствующего ученика в roster после проверки пароля локации. В `ReadWritePaths` службы обязательно должен быть `/var/lib/kiberone-hub/rosters`. При атомарной записи сохраняются владелец и режим доступа исходного файла, чтобы Hub продолжал читать и обновлять список. Проверять выдачу следует для нового ученика, которого ещё нет на сервере.

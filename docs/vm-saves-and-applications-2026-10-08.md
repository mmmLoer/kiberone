# Разрешённые приложения и проверка сохранений на VM

## Интерфейс ученика

Раздел «Приложения» показывает сетку с названием и локальной иконкой только тех установленных приложений, чьи EXE отмечены в `AllowedApps` опубликованных правил группы. Регистр и необязательное расширение `.exe` учитываются одинаково. Явная блокировка имеет приоритет; дубликаты не выводятся. При отсутствии иконки используется первая буква названия.

Обновление правил сразу перестраивает сетку. При смене ученика старые разрешения очищаются; агент повторно получает правила даже при совпадении ревизии. Тьютор продолжает получать полный каталог для выбора разрешений. Переключатель режима блокировки не добавляет в витрину неотмеченные программы.

Карточки отображают доступные приложения; запуск из карточки в этой версии не добавлялся. Есть кнопка обновления каталога, состояние загрузки и объяснение пустой сетки.

Проверены фильтрация, смена правил без повторного сканирования, дубликаты, повреждённые иконки. Headless-тест Avalonia проверяет отображение настоящего PNG и удаление карточки из визуального дерева после отзыва разрешения.

## Проверка файлов на виртуалке

VM: VirtualBox `w3`, Windows `VM-W1`. Использован self-contained `Kiberone.SyncSmoke.exe`, собранный из `tests/Kiberone.SyncSmoke`. Запущены настоящие `ClassroomServer`, `StudentFileSyncClient`, `FileSyncService` и `ProjectGitStore` приложения. HTTP работает внутри VM на отдельном случайном порту. Это интеграционный прогон механизмов сохранения, а не ручной проход кнопок GUI или проверка соединения между двумя физическими ПК.

У проверки отдельная SQLite-база, тестовые ученики и папки. Реальные сохранения, правила браузера, VPN и установленные службы не менялись.

Пройдены 15 сценариев:

1. Загрузка вложенного UTF-8-файла с русским именем папки.
2. Загрузка бинарного файла 4096 байт с побайтовым сравнением.
3. Исключение `.git` и `node_modules`.
4. Повторная синхронизация без лишнего Git-коммита.
5. Изменение и удаление файлов с новым коммитом.
6. Git diff содержит фактические изменения.
7. Восстановление старого коммита передаётся клиенту, возвращая удалённый файл и удаляя новый.
8. Бинарные данные сохраняются при восстановлении.
9. Переключение ветки удаляет файл, существовавший только в другой ветке.
10. Успешное объединение веток передаётся клиенту.
11. Конфликт объединения оставляет текущие файлы без изменений.
12. Локальная резервная копия сохраняет ещё не отправленную работу.
13. Повторное создание клиента использует его сохранённый кэш без лишнего коммита.
14. Второй клиент того же ученика получает его проект в новой рабочей папке.
15. Клиент другого ученика не получает чужие файлы.

Итог: `SMOKE_PASS`, 15/15, код выхода 0.

Для повторения:

```powershell
dotnet publish tests/Kiberone.SyncSmoke/Kiberone.SyncSmoke.csproj -c Release -r win-x64 --self-contained true -o dist/SyncSmoke-win-x64
# Скопировать целиком dist/SyncSmoke-win-x64 на Windows-VM.
.\Kiberone.SyncSmoke.exe
```

Каждый запуск создаёт новую изолированную папку. Не требуется установка .NET SDK на VM.

# Обновления Tutor и Student — 08.10.2026

Исходная версия принята за 2.0.0. Для нового функционала обновлений назначена 2.1.0; затем исправление нагрузки при heartbeat выпущено как 2.1.1, бета — 2.1.1b. Сервер сейчас отдаёт 2.1.1/2.1.1b; старые 2.1.0/2.1.0b сохранены. Источник номера: `version.json`. Правила записаны в корневом `AGENTS.md` и `docs/versioning.md`; повышение номера выполняет `scripts/bump-version.ps1`.

## Что работает

- Сервер `https://nshub.pro` отдаёт отдельные подписанные пакеты Tutor/Student для release/beta. Клиент выбирает канал из версии, а не из переключателя тьютора.
- Tutor проверяет собственное обновление при старте; кнопки проверки и установки находятся в настройках. Установка в стандартную папку пользователя не требует UAC. Для вручную выбранной защищённой папки требуется разрешение Windows.
- Tutor получает оба пакета Student. В смешанном классе каждый Student получает только свой канал. Бета никогда не переходит автоматически на release и наоборот.
- Загрузка закреплена за версией и SHA-256 полученного манифеста. Подпись связывает приложение, версию, размер и хеш. Ошибки, повреждение или неправильный канал отклоняются.
- Опубликованные файлы имеют имена с хешем и не перезаписываются. Старые манифесты сохранены в `.versions/<app>/<version>.json` для завершения ранее начатых загрузок.

API: `/api/update/tutor?channel=release`, `/api/update/tutor?channel=beta`, аналогично `student`. Для файла добавляется `/file`; клиент также передаёт `version` и `sha256`.

## Результаты

- 306 автоматических тестов пройдены; VPN-интеграция исключена.
- 17 тестов правил версий и публикации пройдены.
- Все четыре пакета полностью скачаны с живого HTTPS-сервера. Проверены продуктовая подпись, размер, SHA-256, раздача через Tutor и разделение каналов.
- Настоящий `StudentAgent.StageUpdateAsync` проверен для release и beta: подписанный пакет сохранён и выдан сигнал перезапуска. Приложение и VPN не запускались.
- Настоящий дочерний помощник Tutor заменил EXE изолированной копии: первоначально 2.0.0 → 2.1.0 и 2.0.0b → 2.1.0b, затем реальные опубликованные 2.1.0 → 2.1.1 и 2.1.0b → 2.1.1b. Хешы новых файлов совпали; прежние EXE сохранены.
- Общий механизм применения проверен на реальных скачанных пакетах обоих приложений в отдельных временных папках.
- Для каждого канала выполнены 200 повторных проверок heartbeat на реальном пакете: счётчик полного хеширования EXE не увеличился. Клиенты с актуальной версией не хешируют пакет. Скачивание всегда проверяет и возвращает один и тот же открытый файл; тесты обнаруживают подмену даже с сохранёнными размером и временем изменения.
- После публикации 2.1.1 проверена закреплённая загрузка старого Tutor 2.1.0: сервер отдал HTTP 206 и запрошенные 32 байта правильного неизменяемого файла.
- Hub обновлён; Hub, MailApi, nginx и postfix работают. Первая проверка запуска ошибочно обращалась к `/health` вместо API и откатила исправно запущенный Hub; адрес проверки исправлен, повторное развёртывание успешно.

## Установка и ограничения проверки

Для перехода со старого Tutor 0.10.41 нужно один раз установить новый single-file Tutor. Старый Tutor не содержит нового самообновления. Обновлять Student перед Tutor: старый Student не поддерживает введённую ранее защиту устройства.

Собраны четыре актуальных Inno-установщика 2.1.1/2.1.1b в `dist/installers/channels`. Рабочие установленные клиенты не перезапускались. VPN на рабочем ПК не включался.

Проверки файлового применения не подтверждают весь сценарий клика в GUI, завершения работающего класса и перезапуска установленного Student через SYSTEM-службу на VM. Эти сценарии остаются для интерактивной проверки после входа в VM; здесь проверены скачивание, валидация, подготовка и безопасная замена файлов.

Серверные пакеты опубликованы вручную. Шаблоны автоматической CI-публикации для main/beta подготовлены, но не активированы на сервере: сначала требуется коммит/пуш нового кода и настройка внешнего ключа подписи на машине сборки. Закрытый ключ остался вне репозитория и не переносился на Hub. Локальная ветка beta создана; текущие изменения пока находятся в рабочем дереве.

Проверку скачивания можно повторить:

```powershell
dotnet run --project tools/Kiberone.UpdateSmoke/Kiberone.UpdateSmoke.csproj -c Release -p:KiberoneVersion=2.0.0 -- https://nshub.pro
dotnet run --project tools/Kiberone.UpdateSmoke/Kiberone.UpdateSmoke.csproj -c Release -p:KiberoneVersion=2.0.0b -- https://nshub.pro beta
```

Здесь 2.0.0/2.0.0b — версии тестового процесса для проверки перехода на более новую серверную версию; `version.json` они не меняют.
